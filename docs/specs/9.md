# Spec: #9 Make the list less confusing

Issue: https://github.com/tungphan-agilityio/agilityio-claude-code-training/issues/9
Status: draft

## Problem

The task list is one flat list. It is already sorted (open tasks by due date, undated open tasks next, completed tasks last, see `TaskRules.sortForList`), but nothing on screen says so, so the user cannot tell why a task sits where it does.

Assumed reading (not confirmed by the reporter): the order itself is fine; what is missing is visible grouping. See Open questions Q1.

## Acceptance criteria

- [ ] AC1: Given open tasks due before today, when the list is shown, then they appear together under a heading "Overdue", at the top.
- [ ] AC2: Given open tasks due today, when the list is shown, then they appear under a heading "Today", after Overdue.
- [ ] AC3: Given open tasks due after today, when the list is shown, then they appear under a heading "Upcoming", after Today.
- [ ] AC4: Given open tasks with no due date, when the list is shown, then they appear under a heading "No due date", after Upcoming.
- [ ] AC5: Given completed tasks, when the list is shown, then they appear under a heading "Done", last.
- [ ] AC6: Given a group has no tasks, when the list is shown, then its heading is not shown.
- [ ] AC7: Given tasks inside one group, when the list is shown, then they keep today's order: earliest due date first, ties by id (unchanged `sortForList` behaviour).
- [ ] AC8: Given a search query, when the list is filtered, then only groups with matching tasks are shown, and the empty and no-match messages behave as today.
- [ ] AC9: Given an open task in "Today", when the user ticks it, then it moves to "Done" (and back to "Today" when unticked).
- [ ] AC10: Given the date changes (app left open past midnight, or reopened the next day), when the list is next shown, then tasks regroup against the new today.

## Edge cases

- Task due exactly today: not overdue (`isOverdue` uses `isBefore`), so it goes to "Today", not "Overdue".
- Completed task with a past due date: goes to "Done", never "Overdue".
- All tasks completed: only "Done" is shown; the top bar reads "0 remaining · 0 overdue".
- Only undated tasks: only "No due date" is shown.
- Sort ties: same due date, or both undated, order by id (existing tests for #34 must keep passing).
- `LazyColumn` uses `key = { it.id }`: headings need keys that cannot clash with task ids.
- `TaskListScreen` reads `LocalDate.now()` on each recomposition; grouping must use the same `today` as the overdue label so a task is never shown as "Overdue" under "Today".

## Affected code

- `android-app/app/src/main/java/com/dojo/tasks/domain/TaskRules.kt` (`sortForList`; grouping rule belongs here per CLAUDE.md)
- `android-app/app/src/main/java/com/dojo/tasks/ui/TaskListScreen.kt` (`LazyColumn` items, `DueLabel`)
- `android-app/app/src/main/res/values/strings.xml` (heading strings)
- `android-app/app/src/test/java/com/dojo/tasks/domain/TaskRulesTest.kt`

## Out of scope

- Letting the user pick a sort order or collapse groups.
- Changing the in-group order.
- Persistence (that is #7).
- New dependencies.

## Open questions

- Q1: Is the confusing part the missing grouping (assumed), or does the reporter expect a different order, for example newest first or most recently added first?
- Q2: Is "Today" a separate group, or part of "Upcoming"? (Assumed separate.)
- Q3: Should "Done" be collapsed or hidden by default, or always shown expanded? (Assumed always shown.)
- Q4: Should each heading show a count, for example "Overdue (2)"? (Assumed no.)
