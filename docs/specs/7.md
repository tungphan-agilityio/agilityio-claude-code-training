# Spec: #7 App forgets my tasks

Issue: https://github.com/tungphan-agilityio/agilityio-claude-code-training/issues/7
Status: draft

## Problem

Every time the user reopens the app, their tasks are gone and the five sample tasks are back. Tasks live only in `InMemoryTaskRepository`, which `MainActivity` builds fresh with `withSampleData()` whenever a new process starts.

This ticket is the explicit request that CLAUDE.md's "Never add persistence … unless a ticket asks" rule waits for. Whether it also allows a new dependency is open (Q5).

## Acceptance criteria

- [ ] AC1: Given the user added a task, when the app is swiped away from recents and opened again, then the task is still in the list with the same title, notes, due date and done state.
- [ ] AC2: Given the user edited a task, when the app is reopened, then the edited values are shown, not the old ones.
- [ ] AC3: Given the user deleted a task, when the app is reopened, then the task is not in the list.
- [ ] AC4: Given the user ticked a task as done (or unticked it), when the app is reopened, then its done state is kept. (Assumed yes, see Q2.)
- [ ] AC5: Given the app is installed and opened for the first time, when the list loads, then the sample tasks are shown. (Assumed, see Q3.)
- [ ] AC6: Given the user has deleted every task, when the app is reopened, then the list is empty and shows "No tasks yet. Tap + to add one.", and the sample tasks do not come back.
- [ ] AC7: Given the system kills the app in the background, when the user returns to it, then their tasks are still there.
- [ ] AC8: Given a task created after a reopen, when it is saved, then it gets an id that no existing task uses.
- [ ] AC9: Given the phone is restarted, when the app is opened, then tasks are still there. (Assumed, see Q1.)

## Edge cases

- Sample data is built relative to `LocalDate.now()`: once stored, its due dates must not shift on later launches.
- `InMemoryTaskRepository.nextId` is derived from the max id; after a restart with deleted tasks, a new id must still not clash (AC8).
- Empty list vs first launch: "no stored tasks" and "user deleted everything" must be told apart (AC5 vs AC6).
- Tasks with no due date and with notes containing commas, quotes or newlines must round-trip unchanged.
- Title at exactly `MAX_TITLE_LENGTH` (80) must round-trip.
- Rotation already keeps tasks today (the ViewModel survives config changes); this must keep working.
- `TaskRepository` operations are synchronous by design ("easy to unit test"); storage on the main thread could jank or trigger StrictMode. The plan must decide how to keep tests simple without blocking the UI.
- Stored data that cannot be read (corrupt or from an older format): app must still open.

## Affected code

- `android-app/app/src/main/java/com/dojo/tasks/data/TaskRepository.kt` (interface, `InMemoryTaskRepository`, `withSampleData`)
- `android-app/app/src/main/java/com/dojo/tasks/MainActivity.kt` (builds the repository)
- `android-app/app/src/main/java/com/dojo/tasks/data/Task.kt` (stored shape)
- `android-app/app/build.gradle.kts`, `android-app/gradle/libs.versions.toml` (only if a dependency is approved; CODEOWNERS: Nova)
- `android-app/app/src/test/java/com/dojo/tasks/data/InMemoryTaskRepositoryTest.kt` and a new test for the stored repository
- `CLAUDE.md` / README: "Data is in memory and resets on restart" becomes wrong

## Out of scope

- Sync, backup, accounts or any network (comment Q4 assumes on-device only).
- Export or import.
- Migrating tasks from a previous app version (none exist on disk today).
- List ordering (#9).

## Open questions

The maintainer's four questions on the issue are still unanswered by the reporter:

- Q1: What does "reopen" mean: swipe from recents, phone restart, or coming back later? (Assumed all three, AC1, AC7, AC9.)
- Q2: Should done tasks be remembered too? (Assumed yes, AC4.)
- Q3: Should sample tasks appear only on first launch, or never? (Assumed first launch only, AC5.)
- Q4: Is on-device only OK, no sync? (Assumed yes.)

New from the code:

- Q5: Does this ticket approve a new dependency (Room or DataStore), or must storage use only the platform (a JSON file or SharedPreferences)? CLAUDE.md bans new dependencies unless a ticket asks, and this one doesn't say. This decides the size of the plan.
- Q6: Should CLAUDE.md and the README be updated in the same PR, since both say data resets on restart?
